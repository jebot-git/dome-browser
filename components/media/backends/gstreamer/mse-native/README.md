# Experimental native MSE dependency

> Further in-browser media playback development is outside the current user
> goal. This experimental work is preserved and disabled by default. The browser
> now provides native external-player handoff for unsupported GStreamer media.

This package builds a private, CPU-optimized GStreamer MSE library for Dome's
native media backend. The optional `servo-media-gstreamer/native-mse` Cargo
feature provides Rust sessions and an attachment path in `GStreamerPlayer`;
it is disabled by default and is not exposed to web content yet. DOM objects,
blob URL attachment and delivery to the script task queue remain required.

The input is GStreamer's `1.28.7` MSE source. `upstream.json` pins every downloaded
file; `dome-mse.patch` contains the local changes; `patched-sources.json` pins the
resulting C and header files. Original copyright notices are retained and the
library's LGPL license is included in `COPYING`.

Build as a regular user with a C compiler, Meson, Ninja, GLib development files,
and GStreamer core/base/app development files:

```sh
python3 components/media/backends/gstreamer/mse-native/build_backend.py \
  --build-root /tmp/dome-mse-build --jobs 2
```

An optional `--source-dir` uses an existing upstream source directory instead of
downloading. Hashes are checked in both modes. The build root must be new so a
previous build or its evidence cannot be overwritten accidentally.

The result contains a `stage` directory with the shared library, public headers,
pkg-config metadata and `backend-info.json`. The latter records the library and
patch hashes. The pkg-config variable `dome_mse_patch_sha256` allows a future
consumer to distinguish this dependency from the unpatched system library.
The tool does not install system files or change a desktop session.

The local changes cover source initialization, append completion, separate
audio/video tracks, signed timestamps, sequence groups, append windows, range
removal, abort/EOS/reopen behavior, stream identity, early format queries,
duration validation, sample ownership, terminal decode errors and removal task
cleanup. These changes have controlled native prototype tests; they do not
establish complete MSE conformance. Additional malformed input/format coverage
and browser-level event/lifetime behavior still require validation before
enabling the feature.

Prototype tests and detailed results currently reside in the workspace's
`artifacts/servo-rendering-goal/mse-backend-probe` directory. They include shared
Chromium comparisons, decoded playback, repeated startup/seek runs and GStreamer
leak tracing. They must be brought into the repository's automated tests along
with the native browser integration.

The repository includes a focused ownership regression. With FFmpeg and the
GStreamer leak tracer installed, run it against the staged build:

```sh
python3 components/media/backends/gstreamer/mse-native/tests/check_ownership.py \
  --stage /tmp/dome-mse-build/stage --output /tmp/dome-mse-ownership
```

It decodes 30 frames and fully releases each pipeline and source three times,
then checks that GStreamer shuts down with no live `GstSample` objects. Before
the ownership fixes, shutdown hung on a retained source-buffer-list task; after
fixing that reference, the tracer identified one leaked sample per decoded frame.

A separate failure/lifecycle regression requires the same tools:

```sh
python3 components/media/backends/gstreamer/mse-native/tests/check_failures.py \
  --stage /tmp/dome-mse-build/stage --output /tmp/dome-mse-failures
```

It runs real corrupt MP4 input, removal during append, and removal after append
in separate watchdog-protected processes, with GLib warnings treated as fatal.
It checks ordered completion events, rejection after failure/removal, list
membership, and completion of `gst_deinit()`. The default repeats each case
three times; `--repeats` increases that count. The malformed-input regression
previously tried to join the parser task from its own callback. Active removal
missed abort/completion events; idle removal also left a decoded-track task
retaining the buffer and prevented shutdown. These tests cover native signals;
browser integration must marshal them to the script event loop.

The Rust session layer uses the upstream `gstreamer-mse` bindings. Enabling
`native-mse` requires this exact staged version and patch checksum; the build
rejects the stock system library and stale stages. Use the matching stage for
both `PKG_CONFIG_PATH` during compilation and `LD_LIBRARY_PATH` while testing.
The session queues callback events for its owner and explicitly removes source
buffers before detaching. Its integration test covers negative timestamp
offsets, duration conversion, buffered ranges, errors, removal and unfinished
stream shutdown. Run that test with a synthetic fixture generated by either
native test above:

```sh
PKG_CONFIG_PATH=/tmp/dome-mse-build/stage/lib/pkgconfig \
LD_LIBRARY_PATH=/tmp/dome-mse-build/stage/lib \
DOME_MSE_TEST_VIDEO=/tmp/dome-mse-ownership/video.mp4 \
G_DEBUG=fatal-warnings \
timeout --kill-after=2 60s cargo test -p servo-media-gstreamer \
  --features native-mse --test mse_session -- --test-threads=1
```

Compile the test first with `cargo test ... --no-run` if the initial dependency
build needs more than the watchdog interval. Applications must stop their
player before dropping the session; the integration test waits for every native
task in `gst_deinit()`, so a shutdown hang remains a process-level failure.

The player-facing `MediaSourceInput` trait keeps the player interface independent
of GStreamer. `SharedSession` implements that interface. Set the input before
initializing playback; source setup reports readiness after attachment, allowing
the owner to append bytes after `sourceopen`. MSE inputs bypass download buffering
and derive buffered/seekable time ranges from the source buffers. Stopping the
player removes buffers and detaches the source. Generic player signal handlers
use weak state references, and byte-fed AppSrc callbacks are cleared on stop,
preventing those callbacks from retaining their own player/source objects.

A native dispatch fix also keeps an owner reference across each queued signal
and transfers its release to GStreamer's async worker. Releasing the last owner
inside its own event signal otherwise disposed and joined the currently running
event task. A deterministic Rust regression pauses a close callback while the
main thread drops the owner's last external reference.

Run the Rust session and actual player regressions together:

```sh
python3 components/media/backends/gstreamer/mse-native/tests/check_rust.py \
  --stage /tmp/dome-mse-build/stage --output /tmp/dome-mse-rust
```

The runner compiles three integration binaries, generates its own fixture and
runs each binary three times under a process watchdog, fatal warnings and leak
tracing. It covers software frame delivery, a queued one-second seek, stopping
an unfinished stream, source cleanup, and ordinary byte-fed playback. Those
checks do not establish hardware acceleration, DOM MSE compliance or live X
video compatibility. `--repeats` increases the repetition count.
